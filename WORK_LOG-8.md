## Understanding the issue

Two-round experiment on ARC-AGI-3, **Level 1 only**, across **every public game**:

- **Round 0 (baseline):** a deliberately minimal harness. Plain-code perception turns a
  frame into text (grid size, colour counts, connected-component object list); the model
  gets system prompt + observation + frame diff + last 10 (action, effect) pairs + a
  scratchpad it rewrites each step; it must emit strict JSON
  `{"thought", "action", "args"}`. Budget 200 actions/level + wall-clock cap. 3 seeds
  per game.
- **Phase 2:** log every step to `data/trajectories/<game>/<seed>.jsonl` plus raw frames
  as `.npy` so runs replay exactly.
- **Phase 3:** mine skills **from dev-game trajectories only** — action-effect rules,
  macro-actions, code modules, goal hypotheses. Each skill needs a validation check
  against logged data; failures get dropped.
- **Round 1:** same games/seeds/budget, with the skill library injected into the prompt
  and code modules callable as tools. **Dev and test reported separately; test is the
  real result.**

Deliverables: `results/summary.csv`, `results/figures/` (script-generated), a detailed
`REPORT.md` including the full harness prompt and config, and code in
`harness/`, `learning/`, `analysis/` driven by `python run.py --round 0|1`.

### Assumptions / decisions made where the issue was open-ended

1. **Serving the model: API, not local.** The issue says to serve locally with vLLM or
   SGLang and to use an API provider "only if no GPU is available". The available GPU is
   an RTX 3060 Laptop with **6 GiB VRAM** (`nvidia-smi`, ~1.2 GiB already in use by
   desktop apps). The issue's own figures are ≈16 GiB for 4-bit and ≈29 GiB for FP8, so
   a 27B dense VLM cannot be served on this machine at any useful quantisation. Treating
   this as the "no GPU available" case and using an OpenAI-compatible API endpoint, which
   will be recorded in the report as required. Logged as a decision, not a silent change.
2. **Platform is Windows.** `_runall.sh`-style bash driving is avoided; everything is
   driven from `run.py` so it is reproducible on this machine.
3. **"Level 1 only"** is enforced by stopping the episode the moment the level counter
   advances past 1, and by treating a level-1 WIN as success. Resets are allowed and
   counted, per the issue.

## Open questions / risks

- **Model credentials (blocking the runs).** The endpoint/key pair supplied does not
  authenticate. Needed before Round 0 can execute. Unknown until resolved: what model
  ids the gateway actually serves (`/v1/models` is behind the same auth), whether
  `Qwen/Qwen3.8-27B` is the right id string there, and whether it accepts image input —
  which decides whether the issue's optional "also pass the rendered frame as an image"
  flag can be exercised at all.
- **Rate/spend limits.** The user asked to be told and to stop if limits blow up. The
  harness therefore needs hard per-run token and wall-clock caps and must fail loudly
  rather than silently retry, so a 429/quota wall halts the experiment instead of
  burning budget.
- **Cost is unbounded until measured.** "Every public game × 3 seeds × 200 actions ×
  2 rounds" is on the order of 10^4–10^5 model calls depending on how many public games
  exist. The real number must be estimated from the game count before launching, not
  after.
- **ARC anonymous key.** If the anonymous key is rate-limited or excludes some public
  games, the "every public game" acceptance criterion may need a registered ARC key.
- **Human baselines.** The level score `min(1, human/agent)^2` needs a human baseline
  per game. If ARC does not expose one, those scores get marked N/A, as the issue allows.
