# Tycho (arXiv:2607.28287) — Review

Reviewed 2026-08-23 against the v1 HTML and the released repo (both cached in `refs/`). Section/table
numbers refer to the paper. "The authors report" marks their claims; unattributed judgements are mine.

## 1. TL;DR

- Tycho is a **harness**, not a model: a frontier LLM ("actor") plays through a typed evidence API and may
  delegate to a "builder" subagent that writes a Python world model, verified against recorded transitions
  and searched for plans. The same Opus 4.8 scoring **1.5 RHAE** bare reaches **88.49** inside Tycho (§6).
- The headline is real and officially replayed: **100.00 RHAE, 25/25 games, 183/183 levels** for GPT-5.6
  Sol (7,766 actions) and Opus 5 (6,641), each with a public ARC Prize scorecard (§5.1).
- **⚠️ Most important caveat: public set only, one run per configuration, five of the 25 games used for
  harness development, and the headline Opus 5 run uses a model whose cutoff (May 2026) postdates the full
  public release (25 Mar 2026)** (§7). Your ~0.25% private-set figure is untouched. The authors state all
  of this and call frozen-harness evaluation on unseen games "the decisive next test" (§8).
- The metric is **not** your briefing's formula: Definition 2 caps each level at **115**, not 100, letting
  beaten-baseline levels offset lost ones. 12 of Opus 5's 183 levels sit below that cap. See §6.
- Best negative result: **automatic repair produced the most accurate simulators and the worst model-using
  score** (99.97% vs 45.56% accepted transition match; 83.07 vs 88.49 RHAE — Table 11).

## 3. Problem setup and formalization

A **parameterized rendered deterministic Moore machine** (Definition 1) is `M_θ^ℓ = (S, A, s_0^ℓ, δ_θ, q_θ,
ε_θ)`. Hidden state `s` holds everything — visible or not — determining future behaviour; `δ_θ` maps
(state, action) to a unique successor; being *Moore*, output depends on state alone, and `q_θ(s)` emits
grid, legal-action mask and outcome together. *Rendered*: the observation comes from a renderer `ρ_θ`, not
the state itself. `ε_θ` adds *transition emissions* — animation frames carrying evidence that cannot be
acted on. *Parameterized*: shared mechanics `θ` split from per-level start state `s_0^ℓ`, letting level-1
evidence reduce inference on level 6.

Why not an MDP: it names the distinctions ARC-AGI-3 punishes you for collapsing. Figure 2 shows a scrolling
viewport rendering *identical grids* at two world offsets with different successors under RIGHT;
Proposition 1 proves grid-plus-mask is insufficient. Hence Tycho threads state through the action history
rather than re-parsing frames, and the *typed* history stops the verifier fabricating transitions between
non-consecutive frames.

| Assumption | Status | Where it breaks |
|---|---|---|
| **Determinism** | justified by the turn-based, replay-qualified environment — a benchmark gift, though the authors note a stochastic version needs only a transition kernel | genuinely stochastic or real-time environments |
| **Full observability** | **explicitly *not* assumed** — the formalism's main virtue. Definition 4 lets the renderer abstain per pixel, with *coverage* reported separately from accuracy, so abstention cannot buy apparent accuracy | — |
| **Benchmark priors** (64×64 grids, 16 colors, escalating levels sharing mechanics, HUD categories) | conceded in §7: Tycho is "not benchmark-agnostic" | any transfer outside ARC-AGI-3 |

## 4. Method: the Tycho pipeline

| Stage | LLM or code | What it does |
|---|---|---|
| Frame classification & typed recording | code | tags every frame by role (Def. 3); animation/terminal/fatal stored apart from ordinary transitions (§4.1) |
| Evidence API `wmlib` | code | `frames()`, `transitions()`, `terminal_events()`, `death_events()`, `animation_index()`, diff/segment helpers (App. C.1) |
| Persistent workspace | code | survives the per-level conversation clear after a consolidation pass; resets archive rather than erase (§4.1) |
| **Actor** | **LLM** | reasons over evidence; **only** component that may call `take_action`. Tools: `ls`, `read_file`, `write_file`, `edit_file`, `run_python`, `set_verbosity`, `invoke_builder`, `take_action` (Table 9) |
| **Builder** | **LLM** | writes/repairs the model; file tools + `run_python` + `edit_function`; **no `take_action`, no recursive delegation** (App. A) |
| Hypothesis language | — | Python program with required `init_state`, `transition`, `render`, `outcome`; optional `observation_variants` and planner hooks (§4.2) |
| Verification | code | replays each level from its first frame; grades a transition when the grid changed **or** the model predicts a change (penalising false motion on a real no-op); checks every claimed cell; tests outcomes against recorded winning/fatal actions (§4.3) |
| Planning | code | searches from the *threaded* replay state, not a re-parse; `plan.py` writes a route with per-step frame hashes, surfaced only while model and hash still match (§4.3) |
| Metareasoning / bypass | policy | governs when actor and builder interact (§4.4) |

The no-world-model baseline receives the *same* evidence API (App. C.1), so the comparison isolates
modeling, not evidence quality.

## 5. Orchestration policies

| Policy | Model editor | Trigger for construction/repair | RHAE | Games | Levels |
|---|---|---|---:|---:|---:|
| No world model | — | never (direct-reasoning baseline) | 79.07 | 19 | 157 |
| Single | actor | actor's discretion | 85.36 | 19 | 162 |
| **Orchestrator** | builder | **when the actor requests it** | **88.49** | **21** | **166** |
| Trigger | builder | automatically, on verifier failure or lifecycle event | 83.07 | 18 | 162 |

**"Actor-requested delegation" operationally:** the actor calls `invoke_builder(reason?)` at its own
discretion — no gate, no schedule. Trigger instead fires on a *fixed* verifier gate (App. C.2): accepted
transition match < 0.999, coverage < 0.75 or vacuous, model absent/invalid, or an outcome contradiction —
plus unconditionally at every new level and fatal reset. The authors note the 0.75 threshold "was fixed
during harness development... not selected by a threshold sweep or varied in an ablation."

Only one comparison survives resampling: orchestrator − no-world-model, +9.42 RHAE, 95% interval
[3.97, 15.76], leave-one-game-out [+7.63, +10.14] (Table 3). Every *inter-policy* interval among the three
model-using policies spans zero. The paper supports "selective modeling beats no modeling" far more
strongly than "delegation beats actor-owned modeling."

## 6. Metrics: RHAE vs official ARC-AGI-3 scoring

```
e_ℓ = min{115, 100·(h_ℓ / a_ℓ)²}   if completed and a_ℓ > 0,  else 0
game RHAE = min{ Σ w_ℓ e_ℓ / Σ w_ℓ ,  100 · Σ w_ℓ c_ℓ / Σ w_ℓ },   w_ℓ = ℓ
```

(Definition 2; mean public-set RHAE is the arithmetic mean over 25 games, §5.1.) The weight `w_ℓ = ℓ`
matches your briefing exactly. Your briefing's per-level score is `min(1.0, h/a)²` — capped at 1.0. **The
paper's caps at 1.15.** Not a rescaling: under a 1.0 cap, beating the baseline earns nothing extra, so
every level must reach baseline efficiency for a perfect aggregate; under 1.15 a level at 115 **offsets**
one below 100 before the outer `min` clips the game to 100. Not hypothetical — §5.1 reports **171 of Opus
5's 183 levels and 167 of GPT-5.6's saturate the per-level cap**, so 12 and 16 do not and are carried by
the surplus.

**So "100.00 RHAE" is a perfect score under the paper's stated formula and its officially replayed
scorecards, but does not establish that the agent matched the human baseline on every individual level** —
which is how your briefing glosses "a perfect score of 100%." Two caveats on my own claim: the paper calls
its formula official (citing ARC Prize Foundation 2026a, with scorecards from deterministic competition
replay), while your briefing hedges its own as "approximately" — **I could not adjudicate** without the ARC
Prize spec, which I did not fetch. And the baseline statistic differs too: the paper uses the
**upper-median first-run human action count**, your briefing **second-best of 10 testers**. The paper's is
the more permissive of the two.

**Game-balanced first-run human-replay midrank** (§5.1) is a separate, cap-free statistic and the more
honest one. Per game the agent is compared against that game's distribution of released first-run human
replays (340 usable, 10–54 per game), ordered lexicographically — more levels wins, ties broken by fewer
actions to the last completed level; beaten replay = 1, tie = 0.5, replay ahead = 0, averaged with equal
weight per game. The authors stress it is the expected midrank for a uniformly sampled game and replay, not
one human's percentile across 25 games, because the public files lack participant identifiers (§7).

## 8. Critical assessment

Established: on the 25 public games, a strong evidence layer plus selective LLM-authored programmatic world
modeling plus a frontier model saturates the public split at ~$3k inference (Table 6), with replayed
scorecards.

| Weakness | Evidence | Flagged by authors? |
|---|---|---|
| **Public set only** — no private/semi-private number anywhere. Your StochasticGoose precedent (12.58% → ~0.25%) is exactly this failure mode | §5.1, §7 | yes, §7–8 |
| **n = 1** — every headline is a single sample. Table 3's bootstrap resamples the **25 games**; its own caption says it measures benchmark composition, *not* run-to-run variability. No seeds, no CIs over runs, no variance estimate exists. The 5.42-pt orchestrator/trigger gap and the whole policy ranking rest on n=1 per arm | §7, Table 3 caption | partly — the bootstrap's limits are stated, its insufficiency is not |
| **Development overlap** — 5 of the 25 reported games (`tr87`, `vc33`, `r11l`, `bp35`, `ft09`) informed harness development and stay in the average | §5.1, §7 | yes |
| **Cutoff contamination** — `ft09`, `ls20`, `vc33` public since Jul 2025; **Opus 5's May 2026 cutoff postdates the 25 Mar 2026 release**, so the best headline run is the one whose model could have seen the whole public set. No audit run | §7 | yes, not adjusted for |
| **Frontier pair not matched** — matched budgets are otherwise well specified (3500 LM calls/game, $750/game, 40 tool steps/turn, 24k answer budget), but reasoning effort differs: GPT-5.6 Sol `max` vs Opus 5 `xhigh` | Table 2 | not claimed as matched |
| **Selection asymmetry** — policy chosen on Opus 4.8 then transferred. Right direction, and cross-family transfer is real evidence, but "best policy" was decided on a different model from the headline | §5.1 | implicitly |
| **Score excludes what the system spends** — Opus 5's 61% action saving costs 15.1k calls and ~$2.99k, ~30–600× the human brain-energy estimate | §7 | yes, candidly |
| **Causality not isolated** — GPT-5.6 follows 634/644 builder recommendations, but actor and builder share evidence; no ablation removes the builder from the frontier runs | Table 8, §5.1 | yes |

Being adversarial is harder than the issue anticipated: §7–8 concede most of this unprompted. My
substantive additions are the **115-vs-100 cap discrepancy**, the **baseline-statistic discrepancy**, and
the point that the paper's own bootstrap cannot bear the weight the policy ranking puts on it.

## 9. The repair paradox

| Diagnostic | Single | Orchestrator | Trigger |
|---|---:|---:|---:|
| Pre-action accepted transition match (Table 7) | 13.9% | 16.2% | **88.1%** |
| End-of-run accepted transition match (Table 11) | 22.24% | 45.56% | **99.97%** |
| End-of-run strict full-frame match (Table 11) | 6.9% | 44.1% | **92.9%** |
| Transition-exact completed levels (§5.1) | 25/137 | 62/155 | **154/162** |
| Pre-action model **execution rate** (Table 7) | 89.3% | 83.5% | **52.0%** |
| Builder calls / LM calls / cost (Tables 8, 10, §5.1) | 0 / 25.6k / $7.27k | 147 / 24.1k / $5.78k | **1,192 / 44.4k / $8.03k** |
| **RHAE** | 85.36 | **88.49** | 83.07 |

**The authors' explanation** is epistemic: transition match shows "whether a simulator reproduces observed
dynamics, not whether it has identified the objective or whether consulting it improves the next action."
Evidence: trigger's level_complete recall is 77.7% vs orchestrator's 20.0%, though no policy predicts the
observed deaths (Table 7); plus `sk48` (§5.2), where an orchestrator run built a gripper-and-block
simulator reproducing transitions exactly, then treated the pictorial HUD as candidate goal predicates —
each reachable in simulation, none terminal in the environment: **13 builder calls, 314 scored actions,
zero levels**, on a game trigger cleared all 8 levels of in the same study.

**My assessment: the epistemic story is well-supported as a phenomenon but under-supported as *the*
explanation for 83.07.** Three things in the paper point to a simpler economic mechanism alongside it:

| Mechanism | Evidence |
|---|---|
| **Trigger's model is far less often *available*** — its 88.1% accuracy is conditional on the ~half of actions where a model ran at all | 52.0% pre-action execution vs 83.5% (Table 7). App. D.2's conservative bound, counting model-less actions as inexact, gives 45.5% vs 13.5% — a large win, nothing like 88 vs 16 |
| **It runs out of budget** — trigger did not merely play worse, it was cut off | 1,192 builder calls vs 147; 44.4k LM calls vs 24.1k; **hits the LM-call limit on 5 of its 7 non-winning games**, the only policy to hit it more than once (Table 10). Figure 10b: it trails at the $100 prefix "because model construction has not yet paid off" and never fully recovers |
| **Its repair loop demonstrably works** — the machinery is not broken, it is expensive | After a rejected prediction it restores an accepted one on the next post-builder action in 66.7% of cases and within five in **94.7%**, vs orchestrator's 39.7% / 47.9% (App. D.2) |

There is also an untested confound the authors flag: trigger's gate fires unconditionally at every new
level and fatal reset, and the 0.75 threshold was never swept (App. C.2) — a cheaper gate might dominate.

So the defensible claim is the weaker one the authors make in §8: transition accuracy and decision quality
are *distinct*, and automatic repair *as configured* buys accuracy at a cost not repaid. "Better world
models make agents worse" is not established. `sk48` shows the sharper truth — an accurate model
**amplifies** a wrong objective.

## 10. Reproducibility notes

**Released** (Apache-2.0, per the repo): harness and agent source, prompt templates, all six paper configs, 51 test
files, workspace API, planner, verifier, runner, both provider transports, replay viewer, and `artifacts/`
with six scorecard manifests plus aggregate metrics. Prompts pinned at commit `f68912a`. **Not released:
the run traces** — no per-game workspaces, model calls, or executable models.

**Requirements** (`docs/REPRODUCING.md`): Python ≥3.12; Docker or Finch, since agent-authored Python runs
in a network-disabled sandbox; `ARC_API_KEY`; and `ANTHROPIC_API_KEY` **or** `OPENAI_API_KEY`. Reported
runs used ARC-AGI-3's cached offline engine, whose cache must be populated first. Traces are **not**
expected to reproduce bit-for-bit; the artifact fixes policy, prompts, tool schemas, evidence flow, budgets
and scoring code. Given n=1 in the paper, a reproduction is as much a variance measurement as a
replication.

| Rung | What it does | Cost |
|---|---|---|
| `make validate` | full test / contract / config / wheel suite | **$0** — no Anthropic, OpenAI or ARC call |
| `scripts/smoke_provider.py --confirm-paid-call` | exactly one paid text+image+tool request | cents |
| bounded game smoke on `tr87` | 2 LM calls, 2 tool steps, hard `$0.50` guard | **≤ ~$0.50** |
| 3 games, Opus 5, cost-capped | orchestrator with per-game ceiling | ~$300–450 |

Per-game Opus 5 cost was $119 mean / $97 median / $303 max, so three uncapped games is ~$300–360, worst
case ~$900. But Figure 10b shows Opus 5 at **98.62 RHAE by a $250/game prefix and 100 by $500**, so a
$100–150/game ceiling captures most of the behaviour, and the $0 and $0.50 rungs de-risk it first.

**Open-weights substitution: attemptable, unlikely to reproduce.** Nothing in the contract requires a
provider, but transports are Anthropic/OpenAI native so a third needs writing — and §6's 1.5 → 88.49 gap
shows the harness *multiplies* a strong base model rather than substituting for one. The authors name
open-weight comparison as future work (§8); it has not been done.

**Conclusion: 3-game reproduction is feasible within a student budget**, so per the issue's condition I am
opening the `[spike]` follow-up issue.

## 11. Positioning vs prior work

| Prior approach | Relation to Tycho |
|---|---|
| **StochasticGoose** (CNN RL) | A different species — trained weights, no LLM, Kaggle-submittable. Comparable only as a public-split score |
| **TRM / CompressARC** | Static ARC-AGI-1 at ~7M and ~76K parameters. Orthogonal, and still your small-model precedents |
| **SOAR** | Shares the "LLM writes programs, execution verifies" core, but on static ARC. Tycho applies it to interactive dynamics within one episode and does no training |
| **Model-based RL / VLM-as-planner** | Tycho *is* a VLM-as-planner, but its world model is LLM-authored Python, not learned latent dynamics. It cites Dreamer and MuZero (§4.2) to argue programs suit *this* benchmark — discrete observations, algorithmic environments, exactly localizable errors — not that programs dominate generally |

**Methodologically better, or better-scaffolded? Both, and the paper lets you separate them.** Scaffolding:
1.5 → 88.49 on the same Opus 4.8 (§6). Modeling on top of it: +9.42 RHAE over a baseline already at 79.07
with the same evidence API. Base model: 88.49 → 100.00 by swapping the model alone. **Most of the gain is
the evidence layer, a smaller slice is selective world modeling, and the final saturation is the frontier
model.** The durable contributions are the formalization (§3), the typed evidence contract, and the
separation of model accuracy from decision quality — the last being what will outlive the scores.

## 12. Relevance to my FYP

### (a) Threat assessment

| Candidate direction | Verdict | Why |
|---|---|---|
| **VLM-as-planner scaffolding** | **substantially obsoleted as scoped** | This is what Tycho *is*, and the public-set headroom is gone (100.00, with Rodionov 98.97 and Schema 98.98 behind it) |
| **Model-based RL with explicit world models** | **pressured, not obsoleted** | Tycho's models are *written* by an LLM, not *learned*; a learned-dynamics agent is still unanswered and is the version that runs inside Kaggle. But you can no longer motivate it with "nobody has shown explicit world models help here" — Table 3 shows they do, and OPINE-World, Rodionov and Schema occupy the space. Shift to *trainable, offline-executable* world models |
| **Curiosity-driven exploration** | **least threatened, quietly validated** | Tycho has no intrinsic-motivation objective; exploration is LLM deliberation. Yet §5.3's `ka59` case — a plan's first action doubling as the discriminating test between two piston-orientation hypotheses — is information-gain exploration achieved by prompting. Motivation, not pre-emption |

**Load-bearing for all three:** every result is public-set, hosted-frontier, n=1. The private set,
reliability, and the Kaggle no-internet constraint are untouched. Your small-model track is not obsoleted —
arguably *better motivated*, since the public split is now demonstrably saturable and the way it was
saturated is competition-ineligible (§13).

### (b) Opportunity — the teacher–student loop

**Tycho's builder/repair loop is a within-episode self-improvement loop, and the authors say so.** Figure 18
draws two coupled loops: inner within-run (observe → world model → plan/probe → act) and outer cross-run
(meta-reflection → experience record → generalize → candidate agent → validation). They state the outer
loop "remains human-mediated" — the *authors* select, implement and validate every harness change (§7) —
and §6 names automating it as the next step. **That is an explicitly open problem in a paper that just
saturated the public benchmark, and it is your second track almost verbatim.** Framing: *Tycho's outer loop
is human-mediated by admission; a teacher–student loop is a mechanism for closing it.*

**Could its verification step be the mechanical verifier for a learnability-style teacher reward?**
Technically yes — App. C.2's verifier is exactly the "cheap, automatic verifier" your self-evolution note
requires, and it emits graded signals (accepted transition match, coverage, terminal recall) rather than
bare pass/fail, which suits a learnability score better than binary reward.

**But this paper is also the strongest warning against doing that naively — the most valuable thing in it
for you.** The repair paradox *is* a verifier-driven improvement loop: trigger optimises against the
verifier automatically, hits 99.97% transition match, and plays worse than the policy consulting it
selectively. `sk48` sharpens it — a simulator reproducing every observed transition amplified a wrong
objective into 314 wasted actions and zero levels. A teacher rewarded on verifier pass-rate inherits that
misalignment wholesale. Your note lists "verifier gaps" as a pitfall; §5.1–5.2 are a fully instrumented
183-level case study of it. **That is citable empirical motivation for tying the teacher's reward to
*downstream task improvement* rather than verifier satisfaction — the SOAR-style bilevel formulation you
were already considering.**

**Distilling a small student from Tycho traces?** Three obstacles: the traces are **not released**, so you
generate them at ~$119/game (~$3k for all 25); **you would mostly distil the harness, not the model**,
since §6's 1.5 → 88.49 gap says the evidence layer carries the performance, making a student *inside* the
harness a component swap rather than a distillation result; and **183 levels is a very small corpus**,
where getting more means the private set (inaccessible) or generating your own environments — which loops
back to teacher-as-environment-generator, probably the more interesting project.

**Recommendation:** the open niche is a *trainable, offline-executable, Kaggle-eligible* agent, motivated by
Tycho's admitted human-mediated outer loop, the repair paradox as evidence that verifier-satisfaction is
the wrong training signal, and the eligibility gap in §13. Tycho is your related-work anchor and ceiling
reference, not your competitor.
